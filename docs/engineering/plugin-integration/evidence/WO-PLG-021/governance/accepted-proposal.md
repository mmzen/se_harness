# Plugin simplification review

Reviewed main: `9acdd08e`. Owner direction: 2026-09-13. 50 identified scenarios.

The old harness skills are disposable. The project has one user. A plugin switch should check the replacement, delete the old copies, and remember that the plugin now supplies the skills.

I removed the migration machinery from the local branch `work/plugin-kiss-20260913-f0cd48ea`. This is a local reviewable change; it has not been pushed, merged or used to migrate your live project.

The wider audit also covers plugin setup, session delivery, edit hooks, packaging and their test machinery. Those additional findings are listed separately from the implemented changes. Automatic edit checks are a product choice: my recommendation is to invoke the harness when needed. Your answer to that question is still pending.

The original “signatures” in migration were hashes and consistency checks, not cryptographic signatures proving who approved an action. Some failure cases are possible, such as interrupted writes. The simplification removes the expensive machinery and handles interruption by rerunning the command.

## Changes made locally

| `tests/test_skill_ownership.py` | 1377 lines | 172 lines |
| `.github/workflows/candidate-evidence.yml` | 804 lines | 580 lines |

The old ownership file contained 53 test methods, often with many subcases. The replacement has 13 small tests, plus an installer integration test. It no longer creates full installations and recursive snapshots for every hypothetical failure.

The command is now:

```text
harnessctl skill-ownership REPOSITORY --provider plugin --plugin-root INSTALLED_PLUGIN --apply
```

Preview by omitting `--apply`. Retry by running the same command again. Existing edits and missing old files do not block it. The remaining lock has one provider choice; it does not pin the plugin version or contents.

## Tests and limits

The full source suite passed: 1,197 tests, 26 skipped. This run preceded the final deletion of unused inventory tests and diagnostic code. After that cleanup, all 68 focused CI, package and migration tests passed, with one skipped. The isolated installed-wheel run passed all 12 runnable migration tests in 0.477 seconds; its one directory-symlink test was skipped because this Windows sandbox lacks that privilege. This is a local timing, not a measured GitHub CI speedup.

The first broad run was affected by this sandbox’s Git ownership setting and a Windows line-ending size check. The passing run used a process-local Git safe-directory setting and normalized the unchanged AGENTS.md checkout to its committed LF text. The report does not count those first failures as passing tests.

Graph validation found 1,563 artifacts, zero errors and 46 existing warnings. Release-distribution validation passed for 14 records, and CLI help succeeded. Doctor and upgrade pass together in the migrated-repository integration test. Running candidate doctor on this checkout still reports the seven existing differences between candidate templates and its installed 0.17.0 root; that is not a successful root-upgrade check.

Linux and native host loading were not run locally. The edited CI keeps the installed migration run on Windows and Linux. No GitHub workflow or live repository migration was triggered.

The code still uses the ordinary harness lock for the rest of the installation. Removing all governance, release provenance or work-order rules was not assumed from this plugin-migration request. The old formal plugin contracts describe the discarded implementation and need a concise replacement before this is presented as an approved governed change.
