# Verification Contract: Verify instruction architecture and enforcement

## Automated checks

- Install into an empty repository and confirm the exact ownership-mode and route model.
- Adopt repositories with empty, populated, Unicode, CRLF, and no-final-newline owner instruction files; confirm all outside-fragment bytes are preserved.
- Reject missing-end, duplicated, nested, reversed, and otherwise malformed managed markers with no writes.
- Upgrade unchanged and customized prior installations through every README managed-to-seed migration branch; confirm deterministic plan, preservation, and idempotence.
- Run preflight against complete and incomplete context, unknown and wrong-type IDs, every ineligible work-order status, broken relations, missing chain nodes, managed drift, and path-escape inputs.
- Confirm successful preflight text and JSON contain the same deterministically ordered reading manifest and no repository files change.
- Confirm pull-request work-order parsing rejects zero, multiple, malformed, or injection-shaped declarations and passes one approved exact ID as data.
- Confirm the installed target workflow uses an exact external distribution integrity pin and does not rely solely on candidate scripts.
- Confirm the self-hosting workflow separates last-release independent baseline checks from candidate checks and labels the assurance source accurately.
- Confirm the external baseline detects a candidate that weakens a previously released validator or managed instruction invariant.
- Confirm the post-publication pin-update procedure makes newly released preflight behavior independently enforceable without rewriting historical release evidence.
- Run fresh init, adoption, safe upgrade, doctor, formal validation, dashboard generation, CLI help, and the full unit suite on Python 3.11 and the local runtime.
- Confirm canonical template and self-hosted file/lock parity after the supported self-upgrade.

## Inspection checks

- Confirm the managed AGENTS fragment has one harness destination and the Claude fragment only imports it.
- Confirm the router links every policy module directly and labels its decision point.
- Confirm the engineering README contains repository/domain navigation rather than duplicated managed policy.
- Confirm context, instruction, artifact, evidence, and human-authority roles are distinguished consistently.
- Confirm required host protections are documented as owner actions rather than reported as automatically enforced.
- Confirm reviewers, rather than automation, remain accountable for semantic diff-to-work-order scope.
- Review the final migration plan and verify no customized target file or historical governance record was overwritten.

## Pass criteria

Every automated and inspection check passes, the artifact graph has zero diagnostics, managed integrity is clean, the full suite passes, output is deterministic, no authority transition occurs, and any platform-specific deviation is documented with a bounded residual risk.

## Required evidence

Retain exact commands, runtime versions, fixtures exercised, results, changed paths, migration outcomes, independent-CI pin evidence, deviations, and residual risks under the implementing work-order ID.
