# Verify progressive discovery and safe instruction migration

## Independence

Expected results come from the reviewed requirements, SPEC-IAR-014 and preserved
input fixtures. Do not generate expected routes, owner bytes or authority
results by copying the candidate's output. Test evidence records actual commands,
exit codes, candidate identity, evaluator identity, platform and input hashes.
No implementation or host tests have run merely because this contract exists.

## Acceptance cases

1. New request: root → DEFINE_CHANGE → selected drafting step/checklist.
   Transient notes stay outside the repository; required definitions are durable.
2. Resume implementation after compaction: exact repository/WO recovered, fresh
   evaluator result, current execution step and lost prerequisites read again.
   A remembered state cannot authorize execution.
3. Verification decision: evaluator-selected step, exact record/evidence and
   human authority inputs; no unrelated release or definition-drafting reads.
4. PR preparation: selected delivery path, exact work-order scope and complete
   diff inputs; no invented approval, push or merge authority.
5. Failed check and uncertain write: actual blocker preserved; affected action
   stopped; read back uncertain effects before any retry. No duplicate apply.
6. Missing evaluator: setup selected; repair does not imply upgrade or publish.
7. Owner exception or definition revision on 0.18.0: limitation is explicit;
   no fabricated command/relation, waived gate or edited accepted history.
8. Two repositories: host switches roots, including different selected releases;
   stale entry/procedure content is not reused as authoritative instructions.

## Installer boundaries

Exercise missing, empty and owner-only AGENTS; recognized LF/CRLF fragments;
mixed owner/managed content; customized and duplicate markers; custom seeded
guides; missing destinations; interrupted write/retry; and already migrated
state. Compare owner bytes before/after. Verify locks, adapters, doctor and
preflight agree on ownership. Run supported migration cases on Windows and Linux.
Record unsupported source releases explicitly rather than claiming universal upgrade.

## Agent-host qualification and reading cost

Record actual host/version, event, selected root/release and delivered text or
stable hash. Cover both startup and post-compaction for each claimed host.
Native event traces are required in addition to unit fixtures. An unavailable
host leaves its claim unverified; do not relabel simulated output as observed.

For each of cases 1–6, list the instruction files/headings read and count unique
whitespace words, including COMMUNICATION.md and every required reference.
List selected formal-artifact reading separately. Compare with the complete
source using the same counter. Each case must avoid loading the full collection;
the root's 1,000–1,300-word budget remains advisory. Report measured values, not
an assumed percentage reduction or guaranteed token savings.

## Required checks and evidence

Run focused tests plus the repository-required full test runner, release
distribution validation, CLI help and doctor. Run selected released validation,
phase-appropriate preflight and handoff checks. Exercise the candidate package
in isolated fixtures; its passing tests do not replace released governance.
Use the exact approved candidate commit for commit-bound verification.

Retain evidence under the selected work order's evidence directory. Include the
source/destination map, link results, reading-cost table, lifecycle comparison,
owner-byte comparisons, native traces, complete declared change set, test logs
and baseline differences. Avoid credentials and unrelated conversation content.
VREC/RLS records must use the supported preparation commands, never hand authoring.

## Acceptance boundary

Each WO may complete its own bounded work, but the complete evolution needs all
three WOs and their combined evidence. A passing file split alone is insufficient.
Human verification acceptance remains separate. Release build, publication and
self-adoption are outside these WOs and need their own selected authority.
