## Material findings and resolutions

- Removing templates also removed the former 0.18.0 custom-guide classification.
  The installer now explicitly classifies those old guides before the existing
  transaction writes anything. It renders only the supported legacy pointers,
  checked against independently extracted public 0.19.0 bytes. Fresh installs
  never invoke that conversion. Existing transaction and ownership rules remain.
- Consumers and tests outside WO-IAR-022 were covered by the separately approved
  WO-IAR-024. Renderer content and size checks remain; only fresh-seed assumptions
  changed. The evidence skill cannot turn a missing current guide into fallback
  permission.
- The full Windows and Linux suites exposed the same broken note link. The
  separately approved WO-IAR-025 changes exactly that link and its adjacent
  description. Original failing runs and the exact patch are retained.
- An early mixed-input focused run was invalidated by editing upgrade guidance
  while it ran. Its integrity failure remains visible. Final full runs used
  stable source inputs and passed. A synthetic fixture lock read and a literal
  versus glob packaging assertion were corrected within the approved test scope.
- A first Windows upgrade rehearsal hit the host path-length limit. The retry
  used a shorter disposable workspace and Git long-path support; it passed.
  Linux package setup initially could not read sandbox-owned build outputs.
  Restoring inherited access on those test artifacts allowed the unchanged
  package bytes to pass. Neither issue changed product behavior.
- The first sdist contained the earlier packaging test. A fresh final build
  includes the corrected test. Both final wheels have exactly the same
  decompressed members, including RECORD, as the wheel tested on both platforms.
  See final-package-comparison.json. These are disposable test builds, not the
  reproducible release build of record.

## Remaining references and limits

The inventory classifies remaining references as current, conditional or
historical; zero text matches is not a requirement. Current migration guidance
names the files being retired. The installer and discovery catalogue retain
0.18.0 compatibility; two skills select legacy guides only for older roots.
Tests and retained observations preserve historical names. The preflight legacy
policy constant and operating-card renderer have no current required-read or
fresh-install role; their removal is outside this work.

Repository-owned notes, glossary and installed files still describe this
repository's released 0.19.0 installation. They do not distribute current product
instructions. Their remaining legacy wording and owner pointers are inputs to a
later adoption review, not permission to delete existing owner content now.
