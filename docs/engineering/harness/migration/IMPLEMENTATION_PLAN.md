# Instruction migration

## Installation and adoption

The versioned-successor decision preserves accepted definitions and history.
Candidate instructions, discovery, integrity and host delivery must qualify
together before a separately authorized release and repository upgrade adopts them.
The installed repository remains governed by its selected release until then.

1. Deliver the compact root and conditional procedures with explicit ownership.
2. Return exact procedure and typed-step reading destinations from the evaluator.
   WORKFLOW.json and QUALITY_GATES.json stay machine inputs.
3. Demonstrate selected-repository root delivery at startup and after compaction
   on each advertised host. Missing delivery blocks the affected action.
4. Before removing a legacy AGENTS or CLAUDE fragment, validate the replacement
   delivery and match the recognized installed fragment. Preserve every owner
   byte outside the block. Refuse custom or ambiguous content before writes.
5. Retire the corresponding lock and readiness requirements in the same successful
   migration. Customized editable guides require an explicit migration plan;
   never replace them silently with the new managed instructions.
6. Apply the owner-edit map only in a separate adoption work order. The installer
   cannot treat owner instructions outside a marker as managed bytes.
7. Update active rule references through REFERENCE_MAP.md. Preserve historical
   meanings, decision-right IDs, actual identities and evidence operands.

Validate clean installation, upgrades, LF/CRLF preservation, refusal, interrupted
writes and retry on supported platforms. Keep native host traces distinct from
simulated tests. A file split alone does not establish delivery or migration safety.

## Deferred capabilities

Owner-configured exception evaluation and generic accepted-definition linked
revisions require separately defined and authorized evaluator changes. Neither
is implemented by this instruction migration. EXCEPTIONS.md and
AMEND_DEFINITIONS.md state the available fallback. Human/Agent wording does not
rewrite legacy machine roles, decision rights or historical authority.
