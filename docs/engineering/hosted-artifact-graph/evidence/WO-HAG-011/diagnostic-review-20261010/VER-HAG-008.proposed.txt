# Check concise authoring without weakening evidence or authority

## Independence

Expected wire inputs come from the current published-in-branch schemas and
SPEC-HAG-008, not from the new client. Compare typed input against independently
constructed raw requests. Compare instruction sections and document bytes with
their identified canonical sources. Read saved state through a separate request.
The selected released governor remains 0.22.1, invoked in its separate environment.

Use installed candidate wheels and packaged plugin guidance on Windows for the
native runs. Retain model, host, client, governor and service identities. Native
agents choose the operations and write the content; no fixture supplies a finished
artifact or workflow sequence. Test labels never grant real decision rights.

## Acceptance scenarios

### EFF-01 — Focused instruction delivery

Inspect both packaged host variants. Selecting a drafting task returns the
applicable shared rules and selected intent or verification checklist, with exact source paths, headings
and identities. Compare each section with the selected resource; no altered or
omitted obligation is accepted. Confirm that unrelated lifecycle/release routes
are not loaded on this path. Exercise missing/ambiguous headings, an altered
resource and a selected-release mismatch: each must be explicit, not a fallback.
Existing repository activation and authority routing must remain functional.

Review where each rule lives. Skills and templates may link to it, but must not
maintain competing copies. Check that small required content can be returned
together and that a file pointer is not reported as proof of reading.

### EFF-02 — Typed input and exact submission

For import, draft-open, create-artifact, revise-artifact and revision read,
compare typed input with an independent raw request to the existing service.
Verify exact file bytes, effective identities, operation, target and versions.
Use a real private project for create/revise/readback. Existing raw mode still
works. A changed key, stale version, conflicting input mode, missing field,
unsafe/linked path and oversized input must retain their defined refusal or
conflict behavior. Credentials must be absent from records and console output.

### EFF-03 — Compact output and recovery

Compare compact fields to the retained full response, including failures,
incomplete findings, document digests and version identities. Exercise small
readable documents and a larger saved result. No base64 extraction is needed
for the normal draft path. Full required findings remain accessible.
Force a lost reply and a local capture failure after remote acceptance. Report
the actual uncertainty; reconcile the original operation key and verify no
duplicate mutation. Existing files and historical evidence must stay unchanged.
