# Capability: Communicate governed engineering work through one managed clarity policy

## Actor and need

A supported coding agent needs to explain one current engineering context to an
operator and draft eligible technical prose without avoidable ambiguity.
Operators and accountable owners need this clarity without losing exact
commands, formal semantics, evidence, or decision boundaries.

## Capability statement

`A supported coding agent can produce a decision-ready operator brief and clear eligible English artifact prose under one managed ASD-STE100-based policy while preserving protected technical content and existing harness authority.`

## Boundaries

- The capability applies only to agent-authored English prose.
- It uses a repository-managed subset of clarity principles and never retrieves
  the external ASD-STE100 standard during execution.
- Operator communication and technical-artifact prose use different strengths.
- It does not approve terminology, definitions, implementation, verification,
  release, or external action.
- Exact and semantically protected content takes precedence over the profile.
- The first portable skill is read-only, explicit-only, and single-agent.
- Existing artifacts are not mass-rewritten for stylistic consistency.

## Outcomes

- One integrity-protected policy is routed by the managed harness.
- Supported agents can apply it during ordinary eligible communication.
- An operator can explicitly request one bounded `harness-operator-brief`
  outcome with a structured result and receipt.
- Artifact-authoring skills can reference the same policy without copying it.
- Ambiguous or meaning-changing simplification stops for one precise decision.

## Candidate requirements

- `REQ-TCM-001`: distribute one managed ASD-STE100-based communication policy.
- `REQ-TCM-002`: preserve protected content and technical meaning.
- `REQ-TCM-003`: apply distinct operator and technical-artifact profiles.
- `REQ-TCM-004`: provide the explicit read-only operator-brief skill.
