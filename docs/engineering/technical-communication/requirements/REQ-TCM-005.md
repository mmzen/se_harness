# Requirement: A generated diagnostic-code index that cannot drift

## Rationale

When a harness command refuses, it prints a short code — `MG001`,
`WEX210`, `E012` — and the message beside it. The assessment of 2026-08-30
scored discoverability 3/10 partly because no page lists these codes: an
operator who wants to know what a code family means, or whether a code even
exists, must read the source. A hand-written index would rot the first week;
the fix is a page generated from the source itself, so the set of codes and
their message text cannot drift, and a test that fails the suite when the
committed page differs from a regeneration.

## Preconditions and trigger

The candidate source under `se_harness/`, `repository_tools/` and the
installed template scripts emits diagnostic codes inside string literals;
the test suite runs; an operator reads `docs/notes/`.

## Required response

- One script scans the candidate source's string literals and extracts every
  code belonging to a registered diagnostic prefix, with the message text it
  appears in and the emitting component.
- A registry inside the script names each diagnostic prefix with its
  component and a one-sentence meaning. Artifact identifiers and
  specification rule identifiers, which share the code shape, are not
  diagnostics and never enter the index.
- The script renders one deterministic Markdown page under `docs/notes/`,
  beginning with a Summary, a how-to-read-a-code prefix table, and the
  per-prefix code tables; the page states that it is generated and how to
  regenerate it.
- A test regenerates the page in memory and fails when the committed page
  differs, when a registered prefix matches no code, or when a known
  diagnostic code is missing.
- The page is indexed in the notes index, and the existing `check` note
  points to it beside its small `WEX` table.

## Failure and boundary behavior

The scanner reads string literals through the language parser, so a code
mentioned only in a comment is not indexed. The hash-locked root copies
under `scripts/` are the released evaluator's files and are not scanned;
the index documents the candidate source. A code that appears with many
different messages lists a bounded number of them and states how many more
exist.

## Constraints

The script is standard-library only (the `repository_tools` import barrier
holds). Output is deterministic: sorted, LF-terminated, no timestamps. The
page follows the owner's writing standard of 2026-08-30.

## Acceptance examples

### Example: normal behavior

**Given** this repository's candidate source,

**When** the script regenerates the index and the suite runs,

**Then** the committed `docs/notes/diagnostic-codes.md` equals the
regeneration, `MG001`, `WEX210`, `E012`, `RID018` and `PRE001` are indexed
under their prefixes, and `WO-ECP-010` and `SPEC-ECP-006` are not.

### Example: failure behavior

**Given** a new diagnostic code added to the source without regenerating
the page,

**When** the suite runs,

**Then** the pinning test fails naming the drift.
