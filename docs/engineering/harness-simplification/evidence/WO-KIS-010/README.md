## Design and implementation review

KISS choice: one small checks list in the existing verification contract and
immutable files in the existing WO evidence folder. This makes required outcome
matching deterministic without parsing prose. A presence-only check cannot
meet the approved requirement. No service, plugin, new formal artifact type,
signature, new diagnostic family or equivalence framework was introduced.

The cost is that new work adopting this candidate gate needs declared checks;
old prose-only contracts remain readable but cannot provide automatic success.
Use approved successor definitions/work orders where the installed lifecycle
does not support an in-place amendment. Root 0.18.0 remains governing here.

The input comparison reuses the existing selected formal/code snapshot plus
installed policy inputs. It is conservative for declared scope and does not
authenticate actor names, protect against forged local records, or prove an
unchanged external environment. Those limits remain visible. Owner review was
selected in DEC-KIS-001; no independent review is claimed.

No managed root policy, prior approval event, historical VREC/RLS, external
repository setting, remote branch or published package was changed.
