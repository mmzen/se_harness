# Verification Contract: Verify the owner-directed Explorer presentation refresh

## Independence

On 2026-08-18 the repository owner reviewed this contract with `WO-DST-017` and instructed `ok go implement`, approving these independent evidence obligations for the bounded implementation. This approval does not judge later evidence or verify a candidate.

Verification derives expected semantics from the active requirements, managed policy, progressive schemas, generator, accepted security boundary, and pre-change browser behavior rather than from the supplied template's appearance. The downloaded file is untrusted implementation input, not verification authority.

## Acceptance scenarios

- Confirm the supplied file's intake hash and record the final repository-contained template digest.
- Confirm both inline script bodies are byte-identical between pre-change `main` and the final template.
- Confirm the five literal question phrases are absent.
- Confirm Overview, Lineage, Readiness, details, relation navigation, evidence, findings, provenance, and controlled outcomes remain reachable.
- Confirm the derived/read-only and gate-navigation boundary copy is visible without script execution.
- Generate twice from the real repository and compare deterministic manifests/resources.
- Exercise search/clear, graph controls, inspector, Lineage history, detail tabs, evidence, Readiness selection, and retry controls.
- Block the 3D CDN and verify that only optional topology degrades.

## Property and invariant tests

- Active and canonical template bytes are equal.
- Inline JavaScript, schema constants, bootstrap marker count, CSP, accepted URL, and dynamic request boundaries equal pre-change `main`.
- Presentation changes are limited to local CSS/static markup plus the accessible `gatePanelTitle` hook.
- Canonical data and generated deterministic resources are unchanged for an identical repository revision.
- Every unchanged-script DOM lookup resolves in final markup.
- No aggregate health, confidence, compliance, verification, or release score is introduced.

## Static and architecture checks

- The focused test retires literal-question assertions and positively asserts the three routes, semantic sections, authority-boundary copy, and absence of the old strip.
- Existing 3D, bounded graph, Lineage, detail, progressive resource, security, and provenance assertions remain enabled.
- No generator, CLI, Python behavior, schema, workflow, release support, architecture, or ADR change.
- Formal validation and phase-appropriate preflight pass.

## Security and privacy checks

Require exactly the accepted 3D URL, same-origin progressive fetches, no repository-data transmission, event-handler attributes, dynamic import, storage, cookies, telemetry, or new dependency. Run hostile closing-script, bootstrap-sentinel, markup, URL, Unicode, long-value, missing-target, cycle, and corrupted-resource fixtures; content must remain inert and failures contained.

## Performance and resilience checks

Confirm context-node, Lineage-node, history, resource-count/byte, content, timeout, and retry bounds are unchanged. Exercise rapid selections and stale-request races. Check supported widths for page overflow or hidden controls.

## Manual assessments

At wide, medium, and narrow widths, confirm the refreshed layout matches the supplied design; the removed strip leaves no unexplained gap; semantic routes remain discoverable; Readiness distinguishes Explorer groupings from managed gate policy; focus order and names are clear; color is not the only meaning; and long untrusted text is contained. Review keyboard-only navigation with the CDN available and blocked.

## Evidence retention

Retain authorization, intake/final hashes, source-to-final deviations, changed paths, preflight manifests, commands/exit codes, test counts, lock digest, script/CSP/URL comparisons, deterministic hashes, hostile/failure fixtures, browser widths, keyboard/focus observations, CDN fallback, safe upgrades, residual risks, and unperformed external actions at `docs/engineering/harness-distribution/evidence/WO-DST-017-verification.md`.

## Residual uncertainty

Representative checks cannot prove comprehension for every repository size, display, browser, or assistive technology. The optional CDN retains its accepted risk. Because literal prompts are intentionally removed, evidence must demonstrate semantic discoverability through the remaining routes rather than infer it from matching copy.
