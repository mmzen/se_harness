- `REL-SEH-007`: exact 0.6.0 release unit, compatibility boundary, aggregate-assurance requirements, promotion gates, and rollback policy.
- `WO-RLS-008`: bounded versioning, integration, reproducibility, package acceptance, retained evidence, and aggregate-VREC preparation work.
- Proposed aggregate verification record after an approved and committed candidate: `VREC-SEH-008`.
- Proposed release record after verified aggregate assurance and separately authorized preparation: `RLS-SEH-008`.

The first eight-work-order candidate, `VREC-SEH-008`, and the stopped `RLS-SEH-008` proposal remain immutable historical facts and are not the release path. Candidate validation exposed a real schema-2-to-schema-3 readiness cycle in that sequence.

The approved corrective packet is `REQ-REB-008`, `SPEC-REB-003`, `ARCH-REB-002`, `ADR-REB-002`, `VER-REB-002`, and in-progress `WO-REB-004`. Approved replacement contract `REL-SEH-008` defines a nine-work-order C2, proposed `VREC-SEH-009`, proposed `RLS-SEH-009`, and the exact one-release predecessor-evaluator tuple. Its local implementation and qualification are authorized; no candidate commit, hosted dispatch, VREC/RLS preparation or transition, tag, publication, deployment, maintenance mutation, credential use, external policy change, or root-evaluator upgrade is authorized by that approval.
