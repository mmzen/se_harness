# Workflow Execution Engineering Domain

> Repository-owned index. Formal artifact authority comes from TOML metadata, typed relations, and lifecycle state—not this directory or index.

This domain governs deterministic operation of one selected lifecycle scope. It separates executable workflow mechanics from accountable decisions and makes the same bounded action, validation result, and handoff available to every supported agent host.

## Draft definition packet

- `INT-WEX-001`: make governed workflow execution deterministic across agents.
- `CAP-WEX-001`: operate one governed lifecycle scope predictably.
- `REQ-WEX-001` through `REQ-WEX-005`: bounded scope, transition safety, independent lifecycle planes, honest decision metadata, and canonical handoffs.
- `REQ-WEX-006`: rejected trusted-base diff enforcement proposal, retained as an explicit deferred boundary.
- `SPEC-WEX-001`: provider-neutral focus, atomic transition, preparation, metadata, and handoff behavior.
- `VER-WEX-001`: independent black-box and invariant evidence contract for the five active-scope requirements.
- `ARCH-WEX-001`: provider-neutral transactional workflow-kernel boundaries and tactics.
- `ADR-WEX-001`: proposed choice of a local plan/apply workflow kernel over prose-only, provider-specific, or hosted alternatives.
- `WO-WEX-001`: draft bounded implementation of the approved definition packet, pending architecture/ADR/work-order approval.

No artifact in this packet authorizes implementation until the governing chain is completed and an accountable owner approves a bounded work order.
